# 시스템 구조

## 독립된 센서 경로를 C보드에서 통합

| 보드 | 주요 입력 | 처리 | 전달 결과 |
|---|---|---|---|
| A | 마이크 3채널 | ADC scan/DMA, VAD, 좌우 교차상관, 이벤트 누적, 전후방 조건 | 후방 다섯 방향 코드 |
| B | Flex 5채널·MPU6050 6축 | 2초 윈도우, 185개 특징, 정수 선형 점수, 모드별 후보 제한 | 수어 클래스의 모드별 코드 |
| C | A/B의 SPI 결과·스위치 | 모드 전달, 방향 LED, 단어/문장 누적 | LED 및 16×2 LCD |

C는 SPI1/SPI2 master로 보드마다 결과를 읽습니다. A에는 소음 모드, B에는 간단어/문장 모드를 전달하고 응답 코드를 받습니다. ADC scan의 여러 채널은 순차 변환이며 별도의 동시 sample-and-hold를 구현한 것으로 설명하지 않습니다.

## A보드: 일정한 취득과 이벤트 단위 방향 판정

Timer TRGO → ADC scan → DMA circular buffer로 샘플을 이동합니다. half/full callback 이후 완료된 구간에서 DC 중심값·에너지·VAD를 처리하고, 좌우 마이크의 교차상관을 lag별로 비교합니다. 유효 이벤트 동안 histogram을 누적하고 전방/후방 에너지 조건을 함께 적용합니다.

## B보드: 센서 값에서 분류 입력까지

Flex·IMU 데이터를 200프레임 윈도우로 모아 평균·표준편차·에너지·범위 등 185차원 특징을 생성합니다. PC에서 표준화와 다중 클래스 로지스틱 회귀를 학습하고, STM32에서는 정수 파라미터로 클래스 점수를 계산합니다.

간단어 모드는 다섯 표현의 후보를 사용하고, 문장 모드는 S→V→O 단계별 후보를 선택합니다. 이는 모든 자연어 수어를 문장으로 번역하는 범용 번역기의 성능 주장이 아닙니다.

## C보드: 코드와 표시 상태

A의 방향 코드와 B의 분류 코드를 독립적으로 읽고 LED·LCD 상태를 갱신합니다. 스위치에는 debounce 조건을 두며, 문장 모드에서 IDLE은 이미 구성 중인 문장을 유지하도록 기록되어 있습니다. LCD 함수는 참조 코드에 있으나, C의 독립 프로젝트 설정과 지원 헤더는 완비되지 않습니다.

## 출처
