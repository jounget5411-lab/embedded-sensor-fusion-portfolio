# 개발 과정과 설계 판단

## 센서 취득이 메인 계산을 막는 문제

ADC 변환을 ISR 안에서 시작하고 완료될 때까지 polling하면 데이터 취득 시간이 프레임 처리를 밀어낼 수 있습니다. ADC scan과 DMA circular 모드로 메모리 전송을 분리하고, 메인 루프는 완료된 구간을 처리하도록 구성했습니다.

보고서에서는 GPIO pulse로 처리 구간을 비교했고, 타이머만 toggle하는 조건을 따로 두었습니다. 이를 통해 설정한 타이머 주기와 ADC polling이 추가하는 시간을 분리해 분석했습니다. 공개 폴더는 핀 toggle 전용 측정본을 통합 펌웨어로 잘못 선택하지 않도록 ADC/DMA 호출과 callback을 확인해 선별했습니다.

## 소리의 방향을 이벤트 단위로 안정화

한 프레임의 최대 lag만 사용하면 잡음이나 짧은 소리에 영향을 받을 수 있습니다. VAD·event hangover와 lag histogram을 결합해 유효 구간의 판단을 모으고, 전후방 에너지 비율로 전면 소리를 구분하는 경로를 사용했습니다. 소음 모드는 C에서 A로 전달하는 임계값 선택에 연결됩니다.

## 수어 모델과 데이터의 실제 출처 구분

보존 자료에는 실제 NumPy 특징 데이터로 `LogisticRegression.fit`을 수행하는 제출용 코드와, 임의 예측·무작위 가중치를 만드는 시험용 코드가 함께 있었습니다. 공개본에는 실제 수집 도구와 실제 학습 경로를 선택했습니다. 보고서의 모델 명칭 대신 실제 코드 구조인 다중 클래스 로지스틱 회귀/단일 선형층으로 설명합니다.

원본에 모델 헤더가 존재한다는 사실만으로 모든 데이터 수집·학습·양자화·배포 버전의 연결을 확정하지 않았습니다.

## 확인할 입력 계약

| 경계 | 확인할 내용 |
|---|---|
| CSV → PC 특징 | IMU 열·gyro 포함 여부, 유효 윈도우 길이 |
| PC → MCU 특징 | 구간별 Flex/IMU/norm의 연결 순서와 IMU std/variance 등 통계량 |
| 표준화·가중치 → 정수 점수 | 특징 scale, weight/bias scale, 동일 입력에서 클래스 점수 |
| B → C | 모드별 후보 집합과 2–6 코드의 단어 매핑 |

이 항목은 재현 전에 맞춰야 할 조건입니다. 특징/scale 차이의 존재만으로 최종 시연 전체를 부정하거나, 반대로 같은 헤더 파일명만으로 수치적 동일성을 보장하지 않습니다.
